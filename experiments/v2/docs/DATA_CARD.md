# CacheScope V2 data card

## Purpose and scope

This dataset supports controlled experiments on **pre-answer prompt-compression risk prediction**. Each English task asks for the current owner, release date, or approved budget of a named project. A fixed compressor produces candidates retaining approximately 60% or 30% of the context. The answering model is run on the original and both candidates to obtain observed correctness and regression labels.

All source documents and facts are **synthetic**, generated by AI-assisted Python code. They are not collected from real organizations or independently authored by human annotators. Results describe this controlled factual-extraction setting; they do not establish performance on real documents, open-domain questions, or long-context benchmarks.

| New V2 test tasks | 160 | 160 | Final held-out evaluation |
| **Total included in V2** | **960** | **910** | |

The old 600 task records comprise **550 independent sources plus 50 paired length derivatives**. Each derivative adds unrelated scenery to an existing V1 source while preserving its question and gold answer; it is not an independent new source. All V1 results have already been inspected. Accordingly, every reused V1 task is treated as development data in V2, including tasks formerly called validation, test, or structural holdout. Those old partitions cannot supply a fresh V2 generalization claim.

V2 training therefore contains **720 task records representing 670 independent sources**: the old 600 records plus 120 new records. The new validation and test partitions contain 80 and 160 independent sources, respectively. The old 100-task V1 pilot is excluded from V2 training, validation, test, and the totals above. With two compression candidates per task, the complete 960-task dataset has 1,920 candidate records; candidate rows are not independent tasks.

## New V2 partition design

`make_v2_data.py` fixes the new generation seed at **1111520**. The 360 new sources cover eight high-level structures:

- direct factual statements;
- paragraph headers with following attributes;
- historical values followed by an approved update;
- rejected values contrasted with an accepted value;
- project-to-record reference links;
- tables;
- nested JSON records;
- paired project and attribute directories joined by an identifier.

Each structure has 45 tasks: **15 training, 10 validation, and 20 test**. Every wording/layout family contributes five tasks. There are 72 families in total: 24 training, 16 validation, and 32 test. Family membership is fixed before inference, and no family crosses a split. Text families vary the complete target sentence pattern; structured families vary captions, attribute order, field wrappers, or directory identifiers. The generator does not assign identical wording to different splits by merely changing its family ID.

**All eight high-level structures occur in every V2 partition.** The fresh test measures generalization to new source records and held-out wording/layout families within these known structures. It is not a test on entirely unseen structural types. The table, JSON, and directory formats were also already observed during V1 development.

New task IDs, source IDs, and target entity names are unique. A read-only comparison against all 700 stored V1 task records, including its pilot and derivatives, confirmed that the new task/source IDs do not overlap with V1. Repeated calls to the generator produce identical Python records.

## Context length

Every structure and split contains both named length bands. Longer new sources contain more independent project records with actual distractor attributes, rather than empty repetition. The 360 new tasks contain 184 short-band and 176 long-band contexts.

Lengths below count **context tokens only**, using the bundled Qwen tokenizer. They exclude the answering system instruction, question, and prompt wrapper.

| Generator length band | Observed context-token range |
|---|---:|
| `short` | 142–231 |
| `long` | 478–639 |

The band name `long` is relative to this dataset. Contexts of 478–639 tokens do not justify a long-context evaluation claim. The longest new source has 1,785 characters and 202 whitespace-separated words. Previously generated V1 length derivatives are a separate paired stress set and do not change the scope of the new independent test.

## Gold facts and source audit

Facts are sampled before any answering-model inference. New release dates are in 2027. Amount aliases accept standard USD and numeric forms; date aliases include ISO and conventional month-name forms. Each requested target attribute differs from the corresponding attribute of every distractor project in that source. For update/contrast tasks, the obsolete or rejected value differs from the current value.

`data/source_registry.jsonl` stores the canonical current attributes, obsolete/rejected attributes, and distractor records for each source. The registry is audit material. The answering model receives the rendered context and question; the risk predictor and compressor do not receive the registry, gold answer, or answering-model output as input features.

The source checks cover all 360 new tasks:

- **135 structured tasks:** the emitted table, JSON, or paired-directory text was independently parsed to recover the target's attributes, then compared with the canonical registry and gold answer. The paired-directory check resolves the join through the emitted identifier.
- **225 prose tasks:** a separate read-only audit selected the rendered paragraph containing the target entity, extracted values using name/date/USD grammars, and resolved current versus obsolete values according to the fixed update/contrast sentence semantics. All recovered current values matched both the registry and task gold; all extracted old/new value pairs were distinct. This audit read source text and predefined metadata, not LLM observations.

These checks establish internal consistency of the synthetic sources and labels. They are not external human validation of natural-document quality.

## Observed regression labels

Candidate labels must be derived from genuine answering-model responses scored against the predefined task gold. A regression is `original_correct and not compressed_correct`. Risk-classifier training uses only candidates whose original answer was correct; original-incorrect cases are excluded from that conditional classification target. Policy evaluation retains all tasks, including original-incorrect ones, and counts each task once after candidate selection.

Ground-truth facts, answer strings, answer correctness, response text, and regression labels must not enter pre-answer risk features. Preprocessing must be fitted on training records only. Validation may select model checkpoints and acceptance thresholds; the final test must not guide those choices. Reused V1 observations may inform V2 design because they are explicitly development data.

`data/new_data_audit.json` records split/family counts, length ranges, source checks, assignments, and hashes. These files and the generator were finalized without consulting new answering-model outcomes. They should remain unchanged for this experimental run.

The benchmark has limited vocabulary, explicit facts, fixed question forms, and templated formats. Five tasks share each wording/layout family, so uncertainty estimates should account for family grouping. The 50 old length derivatives share sources with older tasks and must not be counted as additional independent evidence. Fresh V2 results should be compared with baselines on the **same new test set**; a difference from the old V1 test alone mixes model changes with dataset changes.
