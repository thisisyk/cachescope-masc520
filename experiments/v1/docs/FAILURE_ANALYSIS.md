# CacheScope 实测结果与失败分析

本节依据 `results/metrics.json`、`models/training_report.json`、`data/scored_candidates.jsonl` 和 `results/failures.jsonl`，未修改模型、数据或阈值。

## 主测试与泛化

100 个主测试任务中，原文准确率 76%；预先指定种子 520 的 MLP 达到 79%，减少完整输入 token 32.60%，接受 65 次压缩，其中 2 次由对变错、5 次由错变对。准确率变化的分组 bootstrap 95% 区间为 −3 至 +12 个百分点，不能宣称显著提升。RF 同为 79%、减少 30.44%；LR 为 76%、减少 32.07%。

50 个结构留出任务中，原文为 86%，MLP 降至 68%；接受全部 50 次压缩，发生 11 次损害、2 次改善。LR/RF 全部回退原文，保持 86%，没有 token 收益。验证集经验阈值没有迁移成结构留出集上的安全保证。

## 两个可核查案例

**`task-00134`，主测试、`keep_30`。**问题为 “What is the current approved budget for project Coral Main-0134?”；gold 为 `63806`，原文回答 `USD 63806`，压缩回答 `USD 28074`。风险分数 0.09056，低于锁定阈值 0.18250，因此被接受。完整输入从 284 降至 132 tokens。压缩删除四个辅助项目记录，但保留旧预算、正确新预算及 “The replacement sheet records USD 63806.”；这里不能把错误解释为 gold 被删。文本布局变化与回答退化同时出现，具体因果机制尚未验证。

**`ood-00006`，双目录结构、`keep_30`。**问题为 “What is the current owner for project Maple Holdout-0006?”；gold 和原文回答均为 `Nora Stone`，压缩回答为 `Nora Cole`。风险仅 0.00745，仍被接受。输入从 283 降至 136 tokens。候选保留项目对应的 `Item 3`，却删除其属性行，保留的是 `Item 1: owner=Nora Cole`；项目与属性的编号关联因此缺失。保留问题词并不意味着保留答案依赖关系。

## 分类、种子与消融

主测试原文正确的 152 条候选中有 29 条退化；风险分类 AP 为 RF 0.713、主 MLP 0.700、LR 0.665，没有显示 MLP 比 RF 更好的排序。结构留出中主 MLP AP 降至 0.172，低于该集合正例比例 19/86≈0.221，与门控泛化失败一致。

三个预定种子的主测试准确率依次为 79%、76%、77%，token 减少为 32.60%、37.77%、35.47%；520 不是根据测试结果挑选。移除数值／日期特征后为 77%、减少 38.89%、损害 6 次；移除问题重合特征后为 77%、减少 33.88%、损害 4 次。消融均重新训练并在验证集选阈值，工作点不同，不能将差异因果归于某个单独特征。

这些结果支持“受控措辞迁移上有一定压缩收益，但结构泛化不足”的结论。保留失败，不按测试结果重调阈值。

## 补充长度压力结果

50个既有测试来源加入无关附录后，上下文为1,000–1,013 tokens；它们是配对变体，不是新的独立来源。使用原模型和原验证阈值后，MLP、LR、RF全部回退原文，准确率均为72%，没有token节省。简单规则门控为74%、输入token减少17.12%，没有由对变错；始终采用60%候选为62%、减少37.61%，始终采用30%候选为56%、减少65.56%。数字来自 `results/length_stress_metrics.json`，未用于重新训练或选阈值。

当前MLP在新结构上过度接受、在加长输入上完全拒绝，均限制实际用途。这是观察到的决策行为，不能仅由这些结果确定哪个特征导致失败。约1k的合成无关附录压力不等于自然长文泛化验证。
