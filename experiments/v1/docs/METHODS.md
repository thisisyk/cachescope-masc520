# CacheScope 风险预测与策略评测方法

## 研究对象

对任务 \(i\)，原始上下文为 \(x_i\)，问题为 \(q_i\)，参考答案为 \(a_i\)。固定压缩器产生两个候选 \(x'_{i,0.6}\) 和 \(x'_{i,0.3}\)。研究对象是回答模型调用之前的压缩接受决策，而非训练新的通用压缩模型。

对每个候选，记 \(A_i\) 为原文回答是否正确，\(B_{ik}\) 为压缩后回答是否正确。观察到的退化事件为 \(A_i=1, B_{ik}=0\)。分类器只在训练集中的 \(A_i=1\) 候选上学习 \(1-B_{ik}\)，因此输出解释为该训练人群内的条件风险分数。真实推理时原文正确与否未知，程序不会先获取原文答案再决定压缩。

## 固定回答模型和 token 计数

回答模型通过本地 Ollama `/api/generate` 调用，`raw=true`、`stream=false`；系统指令、用户上下文和问题显式包装成 Qwen ChatML。默认配置：

| 参数 | 值 |
| --- | --- |
| 模型标签 | `qwen2.5-coder:0.5b` |
| `temperature` | 0 |
| `seed` | 520 |
| `num_predict` | 24 |
| `num_ctx` | 2048 |
| `num_thread` | 4 |
| 停止序列 | `<\|im_end\|>`、`<\|endoftext\|>` |

实际模型 digest、模型元数据、完整选项、系统指令和运行时信息见 `results/answering_model.json`。温度设为零和固定种子不构成跨所有硬件与版本逐字一致的保证。

本地计数使用 `Qwen/Qwen2.5-Coder-0.5B-Instruct` 的固定 tokenizer，revision 为 `ea3f2471cf1b1f0db85067f1ef93848e38e88c25`。`assets/tokenizer_source.json` 记录来源及 SHA-256。完整输入计数包含系统指令、问题、上下文和 ChatML 标记。代码同时保存 Ollama `prompt_eval_count`，并在标签汇总文件中记录本地计数与后端计数的差异，便于核对计数口径。

## 压缩器

压缩器按句末或换行把上下文分为单元。问题与单元都转为小写词集合并去除固定停用词；排序先比较问题词重合数量，再比较重合密度，最后按原始位置打破平局。

给定目标保留比例 0.6 或 0.3，程序按上述排序尝试加入完整单元，累计 Qwen token 数不超过目标预算；恢复原文顺序后拼接。若没有完整单元能放入预算，则保留排名最高的一个单元，并记录实际比例；不会伪称精确达到目标。候选不短于原文时回退原文。任务指令和问题始终保留。

压缩器只接收上下文、问题、比例和 tokenizer，不接收参考答案、正确性或人工答案位置。该固定算法可能删除跨句归属、更新或否定所需信息，这些风险由真实回答实验观察。

## 特征与监督训练

`extract_features` 接口仅接收原文、问题、压缩文本及两份完整 prompt token 数。固定特征白名单包含 20 项：

| 类别 | 特征 |
| --- | --- |
| 长度 | 原始 token 数、压缩 token 数、删除比例 |
| 重复程度 | 原文和候选的词汇重复率 |
| 问题相关性 | 原文和候选的问题词覆盖率、覆盖率损失 |
| 信息保留 | 词汇保留、数字保留、日期保留、否定词保留比例 |
| 句子结构 | 原始句子数、句子保留比例、原文和候选平均句长 |
| 数值密度 | 原文和候选中的数字出现密度 |
| 位置覆盖 | 原文前 20 个词、后 20 个词在候选中的覆盖比例 |

日期、数字或否定词的保留只是文本统计，不证明与问题有关的事实仍然可恢复。模型不能读取 gold answer 是否消失、回答正确性、模型输出或标签。所有数据划分先固定，`StandardScaler` 只在原文正确的训练候选上拟合。

MLP 为 `d → 32 → ReLU → 16 → ReLU → 1 logit`，CPU 上训练；使用 `BCEWithLogitsLoss`、Adam（学习率 0.001、weight decay 0.0001）、batch size 32、最多 100 个 epoch。正类权重由训练数据的负例数／正例数计算。验证集条件候选的加权 loss 用于早停，patience 为 10，恢复最佳验证 loss 的权重。

模型分别使用训练种子 520、521、522；520 是事先指定的主 MLP，不通过测试结果挑选主种子。传统基线为带训练类别权重的 Logistic Regression，以及 300 棵树、深度上限 8、叶节点最少 3 个样本的 Random Forest。两种消融各使用种子 520：移除数字／日期相关特征，或移除问题重合特征，其他协议保持一致。

若训练集中没有同时出现退化和未退化的候选，程序明确报错，不合成标签或人为配平验证／测试数据。训练样本量、类别分布、软件版本、训练历史与分类结果保存到 `models/`。

## 完整决策策略

每个任务的两个候选分别获得风险分数。对于阈值 \(t\)，只考虑分数不大于 \(t\) 且完整 prompt 短于原文的候选，在通过者中选择 token 最少的一份；都不通过则使用原文。分数和选择过程只使用回答前信息。离线可利用已保存的回答评测该选择，实际部署完成选择后只需一次回答调用。

比较原文、固定 60% 候选、固定 30% 候选、简单规则门控和学习门控。简单规则要求问题词覆盖率不下降，数字和日期保留比例至少 0.6，否定词全部保留；从符合条件者中选择最短候选。

每个学习模型的阈值仅根据全部验证任务选择：在“被接受且由对变错的任务数／验证总任务数不超过 0.02”且“相对原文的准确率变化不低于 -0.02”的候选阈值中，选择完整输入 token 总减少量最大的阈值。全拒绝压缩始终是可用候选。选定后阈值锁定，应用于正式测试和结构留出集。

上述 2 个百分点只是验证集上的经验约束，不是概率置信上界或任何请求上的安全保证。加权训练后的 sigmoid 分数也未经概率校准。测试集上绘制的整条阈值曲线只用于描述，不反向选择部署阈值。

## 指标和不确定性

风险分类指标只对原文回答正确的候选计算，包含 precision、recall、F1、average precision、ROC AUC 和混淆矩阵。只有一个类别时无法识别的指标记录为 `null`，而不是虚构分数。

完整策略在全部任务上计算，每个任务只计一次：

- 任务准确率及相对原文的变化；
- 完整输入 token 总量的减少比例，即 \(1-\sum_i T_i^{policy}/\sum_i T_i^{original}\)；
- 接受压缩的任务比例；
- 有害压缩占全部任务和占已接受任务的比例；
- 原文正确／错误与策略正确／错误的 2×2 计数。

两份候选是同一任务的关联观察，不能当作两个独立测试任务。测试和结构留出结果使用固定种子 520 的 500 次 paired group bootstrap，按 `group_id` 成组重采样，给出准确率变化与 token 减少比例的 percentile 区间。主测试集只有 10 个措辞家族，结构留出集只有三个结构组，区间应结合这种有限独立组数解释。三次训练种子的波动另行报告，不能与样本不确定性混为一谈。

回答调用的已保存 wall time 包含运行顺序、模型加载和缓存等影响；模型风险打分另测批量摊销耗时。二者不能直接证明端到端提速。本实验没有云 API 金额、订阅额度或完整在线服务成本测量，也不把输入 token 减少等同于这些收益。

## 审计、复现和实际贡献

原始响应以追加方式保存，候选表可从缓存重建，固定模型选项和 prompt 参与缓存身份计算。改变模型 digest 或实验设置时应使用新的运行目录／缓存，并保留对应元数据。模型 checkpoint 和 joblib 文件用于本项目复现，只加载自己生成或可信来源的文件。

测试检查源分组、评分边界、特征不读取 gold／标签、训练集标准化、单类别拒绝、模型保存加载和策略选择。模型的训练数据不含 pilot、test 或结构留出集，早停和阈值也不读取测试结果。

代码和合成数据生成规则使用 AI 辅助编写。团队应据实补充两名成员的实际代码、实验与核验贡献，并按课程规定披露 AI 使用。当前实验产物支持后续课程报告和展示，但不代表已经完成公开 GitHub 发布。
