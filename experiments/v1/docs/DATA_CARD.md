# CacheScope 合成事实抽取数据说明

## 数据目的与规模

数据用于研究：在固定回答模型和压缩器下，能否根据回答前特征识别压缩导致的准确率退化，并用风险门控控制压缩使用。

| 集合 | 任务数 | 用途 |
| --- | ---: | --- |
| Pilot | 100 | 开发流程、检查评分与标签分布；不参与训练和正式阈值选择 |
| Main train | 300 | 拟合风险模型和特征预处理，仅使用原文回答正确的候选 |
| Main validation | 100 | 神经网络早停；在全部验证任务上选择策略阈值 |
| Main test | 100 | 设置锁定后的正式任务级评测 |
| Structural holdout | 50 | 三种额外合成结构的留出评测，不用于拟合、早停或阈值选择 |

每个任务具有原文和两档压缩候选。正式 500 任务对应 1,000 个候选记录；50 个结构留出任务对应 100 个候选记录。分类训练记录数还取决于原文回答正确的任务数，应从 `models/training_report.json` 读取实际数量。生成种子固定为 520。

## 来源和生成方式

所有文本、问题和参考答案都是本项目规则生成的合成内容。负责人姓名、项目名称、日期、预算从预定义词表和数值范围抽样，不表示真实人物或项目。参考事实先定义，再填入文本模板，因此参考答案不依赖回答模型的输出。数据不是网络抓取语料，不包含真实客户请求，也不是人工收集的独立问答集。

Main 数据包含三类答案：负责人姓名、ISO 日期、美元预算；包含五类高层结构：

| 结构 | 需要处理的信息关系 |
| --- | --- |
| `direct` | 项目与属性在同一句中直接对应 |
| `header` | 项目标题与后续属性分句关联 |
| `update` | 旧值被已批准的新值替换 |
| `contrast` | 错误值被否定，正确值被明确确认 |
| `reference` | 项目名称通过记录编号关联到属性 |

每类结构有 10 个措辞模板家族，共 50 个家族；每个源任务还包含其他独立项目的干扰事实。上下文通常约 200–350 个 Qwen token，精确最小值和最大值保存在各 `results/*_labeling_summary.json`。这是受控短至中等长度事实抽取数据，不能替代 proposal 中长期希望研究的长文评测。

额外结构留出集使用 Markdown 表格、嵌套 JSON、通过编号连接的双目录。它们由不同生成规则产生，仍属于合成数据，不能称为 human-authored 或真实世界样本。

## 固定分组划分

Main 以措辞模板家族为单位划分；每类高层结构中的 10 个家族固定分成 6 个训练、2 个验证、2 个测试。500 个任务均匀覆盖家族，对应 300／100／100 个任务。具体 `task_id`、`group_id` 和划分见 `data/split_manifest.json`。

同一源任务的原文、问题和两档压缩候选位于相同分组。程序拒绝任何 `task_id` 或 `group_id` 跨划分的记录。Pilot 使用独立事实和编号，仅采用训练家族的措辞；其响应不进入正式训练或阈值选择。

这项划分防止同一措辞家族直接跨集合，却没有把五类高层结构完全隔离。测试结果主要反映对未参与训练的措辞家族的迁移，不能称为未知高层结构的严格分布外结果。结构留出集单独报告，且只有三个高层分组，相关不确定性估计较粗糙。

## 字段

| 文件／字段 | 含义 |
| --- | --- |
| `*_tasks.jsonl` | 每行一个独立源任务 |
| `task_id`, `source_id` | 任务与源事实标识 |
| `split`, `group_id` | 固定划分与措辞／结构分组 |
| `task_type`, `answer_type` | 信息结构与答案类型 |
| `context`, `question` | 实际提供给压缩和回答模型的内容 |
| `answer`, `answer_aliases` | 参考答案及预先定义的可接受表示，只用于评分 |
| `*_candidates.jsonl` | 每个任务的两份压缩候选及真实模型观察 |
| `original_context`, `compressed_context` | 压缩前后的上下文 |
| `keep_ratio`, `actual_context_retention` | 目标与实测上下文保留比例 |
| `original_tokens`, `compressed_tokens` | 完整原文／候选 prompt 的本地 token 计数 |
| `original_answer`, `compressed_answer` | 真实本地回答模型的返回文本 |
| `original_correct`, `compressed_correct` | 归一化 exact match 是否正确 |
| `regression` | 原文正确且压缩后错误时为 1，否则为 0；不代表所有 0 都是安全压缩 |
| `features` | 仅从回答前信息计算的 20 个特征 |
| `*_cache_key` | 指向原始响应缓存中的请求身份 |
| `raw_responses.jsonl` | 按请求追加保存真实回答、耗时、用量、模型标签及时间 |
| `scored_candidates.jsonl` | 候选记录附加各模型风险分数，供策略评测 |

候选文件中同时保存答案和特征是为了审计方便，不表示模型能够读取整个候选字典。训练程序按固定特征白名单取值，预测特征函数不接收参考答案、模型回答或标签。

## 标签来源和评分

标签由本地 Ollama `qwen2.5-coder:0.5b` 的实际回答产生。每个任务分别运行原文和两份压缩候选，完整配置和实际模型 digest 记录在 `results/answering_model.json`。没有 mock、规则回答器或按压缩比例直接编造标签的回退路径。

评分采用有边界的答案提取与归一化 exact match：允许有限的 `Answer:` 包装，姓名忽略大小写并规范空白，日期解析成 ISO 日期，金额规范美元符号、千分位和数值表示。包含正确答案子串但同时含有解释、其他候选值或相互矛盾内容的回答不会仅因子串出现而判为正确。具体实现及边界测试见 `scoring.py` 与测试目录。

原文回答正确且压缩后错误的候选作为风险分类正例；原文正确且压缩后仍正确的候选作为负例。原文本来答错的任务不作为“安全压缩”的负例，也不参与条件风险分类训练，但保留在完整策略评测中。正式评测同时统计由对变错、由错变对、两者均对和两者均错。

## 局限和许可来源

单次固定参数生成不能消除模型输出的硬件、版本或运行时差异。24 个新 token 的输出上限以及 exact-match 格式要求也可能使原本语义上可理解的回答被评为错误；原始响应、结束原因和评分程序均保留以便复核。数据类型、语言、生成词表、压缩器和回答模型均有限，结论只适用于被评测的设置。

数据生成规则和代码使用 AI 辅助编写；没有将它们描述为人工独立采样。合成数据由本项目生成，随项目提供用于课程复现，未复用第三方事实数据集。Tokenizer 来自固定 revision 的 Qwen 项目，来源及文件哈希见 `assets/tokenizer_source.json`，其 Apache 2.0 许可保存在 `assets/LICENSE`。
